# Zerohop

Приватная передача файлов между вашими устройствами, напрямую по локальной сети. Без аккаунта, облака и сервера.

[English version](README.md)

> **Zerohop не проходил независимый аудит.** Приложение создано с упором на безопасность и хорошо протестировано, но сторонние специалисты его ещё не проверяли. Не полагайтесь на него там, где уязвимость может привести к серьёзному вреду.

## Что умеет

- **Передаёт файлы и папки** между привязанными устройствами байт в байт. Прерванная передача продолжается с того же места.
- **Привязка делается один раз.** Вы вводите шестизначный код и сравниваете число на двух экранах. После этого все ваши устройства узнают друг друга.
- **Общий буфер**, по умолчанию выключен: скопировали текст или картинку на одном устройстве и вставили на другом.
- **Работает в фоне**, пока включён буфер, в том числе после перезагрузки.
- **Вы решаете, что принимать**, отдельно для каждого устройства: всегда спрашивать, принимать автоматически, автоматически кроме программ или не принимать.

## Платформы

| Платформа | Состояние |
|---|---|
| macOS | Работает |
| Android | Работает. Отправка буфера требует одного нажатия, потому что Android не даёт приложениям читать его в фоне |
| Windows | В разработке, ещё не проверено |
| iPhone и iPad | Запланировано |

Готовых версий пока нет. Чтобы попробовать, соберите приложение из исходников.

## Безопасность коротко

- Подключаться могут только привязанные устройства. Они опознаются по закреплённым ключам, а посторонний получает отказ ещё при установке соединения.
- Весь трафик идёт через TLS 1.3 с гибридным постквантовым обменом ключами. Режима без шифрования и веб-страницы нет.
- Имена из сети проверяются, и файлы могут попасть только в папку приёма. Программы можно задерживать до вашего разрешения.
- Каждый фрагмент файла проверяется по BLAKE3 до того, как будет принят.
- Ключ устройства зашифрован на диске секретом, который хранит Связка ключей macOS, Android Keystore или защита данных Windows (DPAPI).
- Zerohop держит содержимое буфера только в памяти, удаляет его через две минуты и не записывает на диск и в историю передач. Содержимое, помеченное менеджерами паролей как секретное, не передаётся.

### Известные ограничения

- Пока приложение работает, ключ устройства находится в памяти: защищённые чипы Mac и телефонов не поддерживают Ed25519.
- Тот, у кого в руках ваше разблокированное устройство, может действовать от вашего имени и удалить другие устройства.
- На Android скопированный текст может остаться в буфере дольше двух минут, если в момент истечения срока Zerohop работает в фоне.
- Другие приложения на принимающем устройстве могут прочитать то, что пришло в буфер.
- Если включить необязательный пункт «В Zerohop», приложение на экране телефона сможет отправить свой текст в ваш буфер. По умолчанию пункт выключен.

Полный список угроз и защиты от каждой описан в [модели угроз](docs/threat-model.md) (на английском).

## Сборка из исходников

Нужны Rust (stable), Flutter 3.47, а также:

- **macOS:** Xcode
- **Android:** JDK 21 и Android SDK с NDK 28.2

```bash
cd app
flutter build macos --release
flutter build apk --release --target-platform android-arm,android-arm64
```

Есть и инструмент командной строки:

```bash
cargo run -p zerohop-cli -- --help
```

## Запуск тестов

```bash
cargo test --workspace --features zerohop-core/dev-loopback,zerohop-app/dev-loopback
cargo clippy --workspace --all-targets --all-features -- -D warnings
cd app && flutter test
```

Цели фаззинга описаны в [fuzz/README.md](fuzz/README.md).
